MySQL에서 SAVEPOINT는 트랜잭션 내부에서 언제든 되돌아갈 수 있는 '중간 저장 지점'을 만드는 명령어입니다. 이를 활용하면 트랜잭션 전체를 취소하지 않고, 특정 지점까지만 부분 롤백(Partial Rollback)을 수행할 수 있습니다. [1, 2] 
------------------------------
## 1. 핵심 명령어 3가지

* 
* SAVEPOINT 지점이름; : 현재 상태를 지정한 이름으로 저장합니다.
* ROLLBACK TO SAVEPOINT 지점이름; : 지정한 지점 이후에 실행된 작업만 취소하고 해당 지점으로 되돌아갑니다.
* RELEASE SAVEPOINT 지점이름; : 지정한 지점을 삭제하여 메모리를 확보합니다 (이후 해당 지점으로 롤백 불가). [1, 2, 3] 
* 

------------------------------
## 2. 기본 사용 예시
다음은 [MySQL 실무 및 학습 자료](https://monkeybusiness.tistory.com/865)에서 자주 쓰이는 일반적인 트랜잭션 제어 흐름입니다. [1, 4, 5] 

-- 1. 트랜잭션 시작START TRANSACTION;
-- 2. 첫 번째 작업 수행INSERT INTO users (name, point) VALUES ('홍길동', 1000);
-- 3. 첫 번째 세이브포인트 설정
SAVEPOINT point1;
-- 4. 두 번째 작업 수행UPDATE users SET point = point + 500 WHERE name = '홍길동';
-- 5. 두 번째 세이브포인트 설정
SAVEPOINT point2;
-- 6. 세 번째 작업 수행 (예: 실수로 잘못 입력한 쿼리)DELETE FROM users WHERE name = '홍길동';
-- 7. [선택] 두 번째 세이브포인트 상태로 부분 롤백 (삭제 작업만 취소됨)ROLLBACK TO SAVEPOINT point2;
-- 8. 최종 반영 (홍길동 추가 및 500포인트 지급 상태가 저장됨)COMMIT;

------------------------------
## 3. 꼭 알아두어야 할 특징 및 주의사항

* 
* 트랜잭션 내부에서만 동작: START TRANSACTION; (또는 BEGIN;)으로 트랜잭션을 수동 시작한 상태에서만 의미가 있습니다.
* 중복된 이름 처리: 동일한 이름으로 SAVEPOINT를 다시 선언하면, 기존에 생성되었던 같은 이름의 지점은 자동으로 삭제되고 새로운 지점이 설정됩니다. [6] 
* 최종 종료 시 자동 소멸: COMMIT이나 ROLLBACK(전체 롤백)을 실행하여 트랜잭션이 완전히 끝나면 설정해 둔 모든 SAVEPOINT는 자동으로 사라집니다. [7]
