서브쿼리는 SQL문 내부에서 사용되는 또 다른 SELECT 문을 의미합니다. 요청하신 네 가지 핵심 서브쿼리 개념을 직관적으로 정리해 드리겠습니다. [1] 
------------------------------
## 1. 인라인 뷰 (Inline View)
인라인 뷰는 FROM 절에 사용되는 서브쿼리입니다. [2] 

* 개념: 실행 결과가 마치 하나의 가상 테이블(뷰)처럼 작동합니다.
* 특징: SQL문이 실행되는 동안만 임시로 존재하며, 메인쿼리에서 일반 테이블처럼 조인하거나 가공할 수 있습니다. [3, 4, 5] 

SELECT e.emp_name, d.avg_salFROM employee e,
     (SELECT dept_id, AVG(salary) AS avg_sal FROM employee GROUP BY dept_id) d -- 인라인 뷰WHERE e.dept_id = d.dept_id;

## 2. 동적 뷰 (Dynamic View)
데이터베이스 공학이나 특정 아키텍처 환경에서 인라인 뷰를 다르게 부르는 명칭이거나, DBMS가 제공하는 동적 성능 뷰(Dynamic Performance View)를 의미합니다.

* 인라인 뷰의 다른 이름: 쿼리 실행 시점에 동적으로 생성되었다가 사라지는 가상 테이블이라는 의미에서 인라인 뷰를 동적 뷰라고 부르기도 합니다.
* 시스템 동적 성능 뷰 (예: Oracle의 V$ 뷰): 데이터베이스가 가동 중일 때 메모리 상태, 세션, 성능 통계 등을 실시간(동적)으로 보여주는 읽기 전용 가상 테이블을 뜻하기도 합니다. [6] 

## 3. 단일행 연관 서브쿼리 (Single-Row Correlated Subquery)
메인쿼리의 값을 받아서 실행되며, 서브쿼리의 결과가 딱 하나의 행(Row)만 반환되는 형태입니다. [7, 8, 9] 

* 연관(Correlated): 서브쿼리가 독립적으로 실행되지 못하고, 메인쿼리의 테이블 컬럼을 참조합니다. (메인쿼리 행 수만큼 반복 실행)
* 단일행(Single-Row): 결과가 1건이므로 =, >, < 같은 일반 비교 연산자를 사용합니다. [10, 11, 12, 13, 14] 

-- 자신이 속한 부서의 평균 급여보다 많이 받는 사원 조회SELECT emp_name, salary, dept_idFROM employee eWHERE salary > (SELECT AVG(salary) 
                FROM employee 
                WHERE dept_id = e.dept_id); -- 메인쿼리의 e.dept_id를 참조하는 단일행 결과

## 4. 다중행 연관 서브쿼리 (Multi-Row Correlated Subquery)
메인쿼리의 값을 받아서 실행되며, 서브쿼리의 결과가 여러 개의 행(Row)으로 반환되는 형태입니다. [15, 16] 

* 특징: 결과가 여러 개이므로 =, > 같은 일반 연산자는 에러가 발생합니다. 반드시 IN, EXISTS, ANY, ALL 같은 다중행 연산자를 사용해야 합니다.
* 자주 쓰는 패턴: 특히 EXISTS 연산자와 함께 사용하여 조건에 맞는 데이터가 존재하는지 여부를 확인할 때 가장 많이 쓰입니다. [17, 18, 19] 

-- 부하 직원이 한 명이라도 있는 상사(매니저) 목록 조회SELECT emp_nameFROM employee eWHERE EXISTS (SELECT 1 
              FROM employee 
              WHERE manager_id = e.emp_id); -- 여러 행을 반환할 수 있어 EXISTS 사용
