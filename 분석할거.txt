이고품

create table os (
  OSID integer primary key,
  OS명 varchar(50)
);

insert into os
values
(100, 'Android'),
(200, 'IOS'),
(300, 'Bada');

create table 단말기 (
  단말기ID integer primary key,
  단말기명 varchar(50),
  OSID integer
);

insert into 단말기
values
(1000, 'A1000', 100),
(2000, 'B2000', 100),
(3000, 'C3000', 200),
(4000, 'D3000', 300);

create table 고객 (
  고객번호 integer primary key,
  고객명 varchar(50),
  단말기ID integer
);

insert into 고객
values
(11000, '홍길동', 1000),
(12000, '강감찬', null),
(13000, '이순신', null),
(14000, '안중근', 3000),
(15000, '고길동', 4000),
(16000, '이대로', 4000);

select A.고객번호, A.고객명, B.단말기ID, B.단말기명, C.OSID,
C.OS명
from 고객 A left outer join 단말기 B
on (A.고객번호 in(11000, 12000) and A.단말기ID = B.단말기ID)
left outer join os C
on (B.OSID = C.OSID)
order by A.고객번호;

제시해주신 MySQL 쿼리는 LEFT OUTER JOIN의 특성과 조인 조건(ON 절)의 평가 방식을 이해하는 데 아주 좋은 예시입니다.
작동 원리를 핵심 위주로 명쾌하게 설명해 드리겠습니다.

## 1. 핵심 작동 원리 한 줄 요약

LEFT OUTER JOIN에서 ON 절의 조건은 조인 대상 데이터를 필터링할 뿐, 왼쪽(기준) 테이블의 행을 탈락시키지 못합니다. 조건에 맞지 않으면 우측 테이블의 값을 NULL로 채워 출력합니다.


## 2. 단계별 데이터 처리 과정## 1단계: 첫 번째 LEFT JOIN (고객 A ➔ 단말기 B)

* 기준 테이블 (고객 A): 모든 행(5개)이 무조건 결과에 포함됩니다.
* 조인 조건 (ON A.고객번호 in(11000, 12000) and A.단말기ID = B.단말기ID):
* 홍길동(11000): 고객번호 조건 만족 + 단말기ID(1000) 매칭 ➔ B 테이블 데이터 결합 성공
   * 강감찬(12000): 고객번호 조건은 만족하나 단말기ID가 NULL이라 매칭 실패 ➔ B 테이블 데이터 NULL 처리
   * 이순신~이대로: 고객번호가 조건(11000, 12000)에 맞지 않으므로, 단말기ID 비교조차 하지 않고 전부 B 테이블 데이터 NULL 처리

[1단계 중간 결과]

| 고객번호 | 고객명 | 단말기ID(B) | 단말기명(B) | OSID(B) |
|---|---|---|---|---|
| 11000 | 홍길동 | 1000 | A1000 | 100 |
| 12000 | 강감찬 | NULL | NULL | NULL |
| 13000 | 이순신 | NULL | NULL | NULL |
| 14000 | 안중근 | NULL | NULL | NULL |
| 15000 | 고길동 | NULL | NULL | NULL |
| 16000 | 이대로 | NULL | NULL | NULL |

## 2단계: 두 번째 LEFT JOIN (위 결과 ➔ os C)

* 조인 조건 (ON B.OSID = C.OSID):
* 앞선 결과에서 홍길동만 B.OSID 값(100)을 가지고 있습니다. ➔ os 테이블의 100(Android)과 매칭 성공.
   * 나머지 고객들은 B.OSID가 모두 NULL이므로 os 테이블과 매칭되지 않아 C 테이블 데이터 NULL 처리.

## 3단계: 정렬 (ORDER BY A.고객번호)

* 마지막으로 고객번호 오름차순으로 최종 정렬되어 출력됩니다.


## 3. 최종 쿼리 결과 항목

| 고객번호 (A) | 고객명 (A) | 단말기ID (B) | 단말기명 (B) | OSID (C) | OS명 (C) |
|---|---|---|---|---|---|
| 11000 | 홍길동 | 1000 | A1000 | 100 | Android |
| 12000 | 강감찬 | NULL | NULL | NULL | NULL |
| 13000 | 이순신 | NULL | NULL | NULL | NULL |
| 14000 | 안중근 | NULL | NULL | NULL | NULL |
| 15000 | 고길동 | NULL | NULL | NULL | NULL |
| 16000 | 이대로 | NULL | NULL | NULL | NULL |


## 💡 주의 및 팁 (많은 개발자가 실수하는 부분)
만약 안중근(14000), 고길동(15000) 등의 데이터 자체를 결과에서 아예 제외하고 싶었다면, 고객번호 IN 조건을 ON 절이 아니라 WHERE 절에 작성해야 합니다.

* ON 절에 쓰면: 조건에 안 맞아도 출력됨 (우측만 NULL)
* WHERE 절에 쓰면: 조건에 안 맞으면 행 자체가 탈락됨


혹시 이 쿼리를 통해 실제 구현하고 싶으셨던 특정 추출 조건이 있으시다면 말씀해 주세요. 올바른 SQL 수정안을 제안해 드리겠습니다.

제시된 해설처럼 3차 정규화까지 마쳤을 때 총 7개의 엔티티가 도출되는 과정은 다음과 같습니다.
제 1, 2, 3 정규화 원칙에 따라 기존 엔티티들이 어떻게 분리되는지 단계별로 명쾌하게 설명해 드리겠습니다.

## 1. '학생' 엔티티의 정규화 (4개 엔티티 분리)
기존 '학생' 엔티티는 여러 종류의 정보가 섞여 있어 정규화 대상이 됩니다.

* '학과' 엔티티 분리 (제3정규화)
* 학생 테이블 내에 학과번호와 학과명이 있습니다.
   * 학번 $\rightarrow$ 학과번호 $\rightarrow$ 학과명 구조로, 기본키가 아닌 일반 속성 간에 종속 관계(이행적 함수 종속)가 존재합니다.
   * 따라서 [학과](학과번호, 학과명) 엔티티로 분리됩니다.
* '교수' 엔티티 분리 (제3정규화)
* LAB실이용승인교수번호에 따라 LAB실이용승인교수명이 결정됩니다.
   * 이 역시 이행적 함수 종속이므로 [교수](교수번호, 교수명) 엔티티로 분리됩니다.
* 'LAB실이용신청' 엔티티 분리 (제1정규화 - 반복 그룹 제거)
* LAB실이용신청일1, 2, 3, 4와 같이 동일한 속성이 여러 개 나열되어 있는 반복 그룹 상태입니다.
   * 반복되는 속성을 별도의 엔티티로 독립시켜야 하므로 [LAB실이용신청] 엔티티가 도출됩니다.
* 남은 [학생] 엔티티
* 위의 속성들이 빠져나가고 순수한 학생 정보(학번, 성명 등)만 남은 [학생] 엔티티가 유지됩니다.

💡 결과 (4개): 학생, 학과, 교수, LAB실이용신청


## 2. '도서대출' 엔티티의 정규화 (3개 엔티티 분리)
문제 조건에서 "하나의 대출자(학생)에 대해 하나의 대출번호로 여러 개의 도서를 대출/반납한다"라고 명시되어 있습니다. 즉, 영수증 하나(대출번호)에 여러 책이 찍히는 구조입니다.

* '대출도서' 엔티티 분리 (제1정규화 - 반복 그룹 제거)
* 하나의 대출번호에 여러 도서가 매핑되므로, 대출 상세 내역에 해당하는 [대출도서] (또는 대출상세) 엔티티가 분리되어 나와야 합니다. (이 엔티티에는 대출번호, 대출도서번호, 반납일자 등이 포함됩니다.)
* '도서' 엔티티 분리 (제2정규화 - 부분 함수 종속 제거)
* 대출도서번호에 종속되는 도서 고유 정보인 도서명, 출판사명, 출판년도, 대표저자명, ISBN 등은 대출 행위와 상관없는 도서 자체의 속성입니다.
   * 따라서 핵심 마스터 테이블인 [도서] 엔티티로 완전히 분리됩니다.
* 남은 [대출] 엔티티
* 도서 상세 정보가 빠져나가고, 대출 행위의 큰 틀만 담은 [대출] 엔티티(대출번호, 대출자번호, 대출일자 등)가 남게 됩니다.

💡 결과 (3개): (도서)대출, 대출도서, 도서


## 짚고 넘어가기 (최종 요약)
각 영역에서 도출된 엔티티들을 모두 더하면 다음과 같습니다.

   1. 학생 (기본 정보)
   2. 학과 (학생에서 분리)
   3. 교수 (LAB실 신청 승인 교수 정보 분리)
   4. LAB실이용신청 (반복 속성 분리)
   5. (도서)대출 (대출 마스터 정보)
   6. 대출도서 (1개 대출번호에 여러 도서가 속하므로 분리된 상세 정보)
   7. 도서 (도서 고유 마스터 정보)

따라서 총 7개의 엔티티가 도출되므로 답은 3번이 됩니다.
